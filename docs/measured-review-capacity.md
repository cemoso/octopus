# Measured complete review admission

Part of #841. The `anthropic-complete-review-v1` policy can prepare one complete changed-source request when the ordinary default allocation is incomplete. It only applies to the exact model `claude-fable-5-1` through the direct Anthropic adapter and endpoint. The model is selected once from the ordinary baseline input; admission never changes a model pin, reasoning effort, output allocation, severity or confidence policy.

An absent `MAX_DIFF_CHARS` permits this policy. Every present value, including an explicit `350000`, a fractional cap, an empty string or an invalid value, retains the existing bounded behavior and cannot authorize expansion. Candidate preparation reuses the existing inventory, patch parser, generated/ignored matchers and versioned binary evidence. It requires all eligible text hunks, complete inventory and known head/base revisions, within the lower of 1,500,000 characters and the existing fetch allowance. It never makes a larger partial selection. Excluded binary content remains unreviewed.

The selected complete diff feeds the existing retrieval, rule, tool and prompt builders. Admission then operates on the same frozen Anthropic body used for generation, including cache blocks, adaptive thinking, resolved effort and `stream: true`. The count projection removes only `max_tokens` and `stream`; unsupported fields or any changed user-message content are refused. The existing system cache marker transformation is checked separately and both system identities are recorded. Neither serialized request may exceed 4 MiB in UTF-8.

Fresh model metadata and token count use the same SDK client and account route as generation, without SDK retries. Metadata has a five-second deadline; counting has fifteen seconds. Null, mismatched or unsupported metadata cannot authorize expansion. The policy requires the model to support the selected effort and adaptive thinking. Counting sends the assembled source and context to Anthropic; it is not a local calculation.

The token predicate is `count + max(4096, ceil(count × 10%)) + effective max_tokens ≤ min(1,000,000, metadata.max_input_tokens)`. The effective output maximum must also be within both the model metadata and 128,000. The existing Fable adapter raises the caller's 8,192-token allowance to 64,000; that effective maximum is reserved once, including thinking. Output or effort is never reduced to gain input capacity.

The conservative primary-generation estimate must be at most $15 after platform markup. Input/output prices use the higher of the valid catalogue rate and the central Fable 5.1 floor of $10/$50 per million tokens. Every admitted input token is estimated at the most expensive cache-write tier present in the frozen body: 2× for one hour, 1.25× for five minutes, or 1× without caching. Cache hits are not required to stay under the admission allowance. This applies to BYOK too. Missing or invalid pricing is refused. Existing usage settlement and billing gates remain in place.

The worker passes the actual pg-boss start, expiration and abort signal. The earlier of the job's start-based deadline and the callback-entry duration is converted to a monotonic remaining lifetime. Admission reserves sixty seconds for publication and requires at least six hundred seconds for primary generation. The stream timeout is no more than fourteen minutes or the remaining job lifetime minus publication reserve. Final admission rechecks the current `reviewing` claim, request version, remote head and base, paused state and billing for the frozen provider. Metadata/count must still be younger than sixty seconds and the payload digest unchanged at dispatch. Findings recovery shares the remaining job window and uses no SDK retries. Queue settings and deadlines are not increased.

The immutable assessment JSON contains a separate `capacityAdmission` receipt: candidate identity and prepared source counts, metadata/count identities, effective budgets, pricing, request bytes, deadline and decision. Metadata and count do not count as generation receipts. A typed refusal before generation marks eligible files as omitted with zero supplied characters/hunks while retaining acquired patch hashes and exclusions. It cannot fabricate a zero-cost response or a no-model success. A local stream-call start is only a local observation; it does not prove provider receipt. A transport failure after that boundary keeps its supplied-source evidence and remains an incomplete assessment.

Successful admission still requires the existing completed provider response, request provenance, source coverage, findings validation and score gates. It does not establish a passing review. The $15 allowance is a conservative per-primary admission estimate, not an invoice guarantee, credit reservation or whole-workflow cost cap. Preparatory calls and findings recovery have separate costs. Existing queue/reaper retries after ambiguous failures can spend again; this change does not provide a durable dispatch ledger or exactly-once billing. Batching and billing settlement are separate work.

Final billing eligibility must still describe the prepared client's credential route. The router compares a freshly read organization key to its original value only in memory, after the billing/currentness check. Adding, removing or rotating a BYOK key refuses the prepared attempt; it never swaps the counted client or stores credentials in evidence. The remote revision fetch precedes the final billing and claim reads so a pending remote request cannot leave a stale claim snapshot ready for dispatch. These are bounded currentness checks, not an atomic dispatch fence or credit reservation.

Adaptive attempts also check cancellation/expiration before and after post-primary retrieval and validation and immediately before publication. The validator's model, scope and confidence/severity behavior remain unchanged. An existing in-flight validator/retrieval call that lacks cancellation support may finish, but its result cannot authorize a successful expired review. Those stages have separate costs and time outside the $15 primary estimate. Post-primary expiry retains supplied hunks and generation evidence. If the completed assessment was already committed when expiry is detected, one new incomplete processing attempt references that immutable record; the main summary points to the incomplete final outcome and no success check is issued by that expired path.

Validation uses synthetic source and stubbed metadata/count/generation/database interfaces. A character measurement of a real PR does not establish token fit, provider access, final prompt size, cost or completion. An authorized account-specific preflight is required before making those claims.
